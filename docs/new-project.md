# 新项目：修改配置，不修改渲染源码

## 选定一套节奏

`cinematic120` 为 120 秒横屏电影感；`classic220` 为 220 秒竖屏旧版讲述。视频的时长、帧率、画布和分镜时间槽保持预设值。换标的时替换事件日期、标签和字幕，沿用到达秒及停留时长；任意新时长需要重新设计与验证，不属于首版配置范围。

先 `init` 复制示例，在复制目录里编辑 `project.json` 和 `daily.csv`。可填写[制作单](../templates/production-template.md)作为审核依据，或使用 [AI 提示词](../templates/ai-new-project.md)协助准备配置。

电影感预设的 `E01`—`E04` 是渲染器用于标签布局和比较展示的固定分镜节点 ID，请保留 ID 及现有到达／停留节奏，只替换本期日期与文字；无需把它们继续称作韩股事件。第一事件使用 CSV 首日且 `arrival` 为 0，最后事件使用 CSV 末日。其余事件仍须严格按交易日升序、时间槽不重叠。日股预设的事件须在 218 秒前结束，保留最后 2 秒全景。

## 日线数据

CSV 使用 UTF-8，表头固定为：

```csv
date,close
```

每行是真实交易日，日期为 `YYYY-MM-DD`，`close` 是有限正数。日期唯一且升序。明确指标是价格指数、总回报指数或复权价格；同一视频使用一种口径。保留全量日线，不用几个人工锚点替代，不补造停牌或休市日的价格。替换 CSV 后重新核对首尾、极值、长缺口和异常跳变。

`data` 指向行情文件，例如 `daily.csv`。配置里文件路径相对 `project.json` 所在目录解析。`data_source` 与 `display.source` 应改为本期实际来源，并更新项目旁的 `sources.json`，保存原始 URL、获取日期、口径、过滤规则和可用条件。

## 配置要一起改

| 配置项 | 填写内容 |
| --- | --- |
| `name`、`instrument` | 项目名、标的中文名、代码、单位、指标口径与是否含分红 |
| `display` | 画面标题、副标题、标的标签、来源、区间说明、片尾文字、单位 |
| `events` | 唯一 ID、实际交易日 `date`、短标签 `label`；保留到达秒 `arrival` 与停留秒 `hold` |
| `chapters`、`captions` | 电影感片的章节与字幕，时间码对应现有分镜槽位，删除旧标的文案 |
| `contexts` | 历史背景、显示日期范围和来源；日期可以是事实发生日，但行情事件仍须对应交易日 |
| `chart` | 电影感片的纵轴、视窗与阶段颜色口径；换标的须重新适配数值域 |
| `comparisons` | 电影感片的基准日、关口与关口日期，均取当前 CSV 的事实 |
| `audio` | 电影感片的配乐与事件提示点；事件 ID 和到达秒与事件表保持一致 |
| `publishing` | 标题、简介、话题、封面分行标题与副标题 |

示例配置是完整可运行文档，优先以当前示例和命令的 `--help` 为准，不必自行猜测省略字段的默认行为。不要仅换顶部名称而遗漏字幕、比较文字、背景事件和发布文案。

更换数值域后，可先将电影感配置的 `chart.auto_scale` 设为 `true`，使用覆盖全量最高收盘的统一纵轴；这会清除示例的阶段纵轴切换。需要保留阶段切换时，关闭自动缩放并重新设置 `y_max` 与 `axis_transitions`，逐阶段检查可见价格是否完整。`comparisons.demo_reference_date`、`threshold_date` 必须是 CSV 中的交易日，`threshold` 改成本期需要说明的关口。

`publishing.cover_lines` 固定两行，每行 1—10 字符；横版将两行合成一个主标题，竖版分行显示。简介里的话题直接写入 `publishing.description`，`topics` 是供编辑参考的列表，命令不会自动追加。

**事件只填写日期和说明，不填价格。** 工具从 CSV 的同日真实收盘获取事件点位。休市日新闻请登记事实日期，另选图上实际交易日；不要把新闻日期改写成虚构报价。首尾、事件日和比较日期必须落在数据中，事件按时间顺序推进。

字幕含具体日期、价格、百分比时应根据本期数据重新计算。以收盘点位超过关口为主题时，核对是否真是区间内或历史上的“首次”；只有覆盖足够长的完整数据才能支持“历史首次”。

## 先短预览，再全片

1. 环境检查通过；原样示例短预览可运行。
2. 替换 CSV 与全部文字；检查事件顺序、极值、比较基准与时间槽。
3. 看新项目短预览，生成横竖封面，核对字体和手机缩略图可读性。
4. 制作全片并验收；检查关键节点及每个分段衔接，保留最后报价后的片尾。
5. 完整观看、试听并记录问题。视频最高点不一定是最后一天，封面与片尾都应保留高点之后的真实走势。

新项目应保存自己的来源记录、配置、CSV 与验收结果。大体积输出默认忽略，不需要提交到模板仓库。若制作另一套风格或时长，先标记为实验版本，直到完成新的动画与声音验证。

## 日经可选配乐

`classic220` 可通过 `audio.score: "energetic220"` 启用原创 140 BPM 配乐，完整例子见 `examples/nikkei/project-energetic.json`。省略该字段仍为静音；时长与事件时间保持原契约。配乐编排与来源说明见 [日经完整版配乐](energetic-score.md)。

## 导入已完成的配乐母带

classic220 也支持 `audio.score: "external220"`，同时填写 `audio.file`（220 秒、单音轨的混音文件）与 `audio.provenance`（来源及适用条件的 JSON 文件），两者相对 project.json 解析。母带应已经包含需要的事件音效和首尾编排，此入口不会自动叠加旧配乐、延长或循环素材。

工具转换为 48 kHz 双声道 PCM；音源和来源记录均进入缓存指纹，输出母带另校验哈希，独立 verify 会重新核对当前音源。最终 AAC 的响度与真峰值仍需通过验收；导入并不自动证明音量合格。模型生成音频应记录模型、版本、提示词、随机种子、编辑与来源条件，不把 MIDI 编曲称作模型人声输出。
